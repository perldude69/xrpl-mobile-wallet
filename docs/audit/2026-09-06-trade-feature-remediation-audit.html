Remediation verification

FindingFix and verification
XRW-26
Raw exception text in Trade UI		 All snackbars in lib/ui/trade/trade_dashboard_screen.dart now render fixed text from the new top-level tradeFailureMessage(Object) — no e.message / e.toString() anywhere in the file (source search clean). Engine-result codes (public XRPL constants) are still shown. Test test/ui/trade/trade_dashboard_helpers_test.dart feeds seven exception shapes carrying a marker string and asserts the marker never appears in the output; PaymentOperationException surfaces only its own fixed stage constant.
XRW-27
Maintainer host as default RPC / submit endpoint		 EndpointPreferences.mainnetHttpCatalog now leads with xrplcluster.com; rpc.rich-list.info moved to last and excluded from defaultHttpIds — it is opt-in only, labelled "(maintainer)". The empty-selection fallbacks in _builtInUrls and _clean now fall back to the default set rather than the raw catalog, so deselecting every node cannot silently re-enable the maintainer host. lib/config/network_id.dart already led with the public cluster, so the two catalogs now agree. Tests: default RPC is a neutral public cluster and never includes rpc.rich-list.info; explicit opt-in works; empty set falls back to the default set.
XRW-30
Trade offered to Ledger wallets it can't sign for		 Trade signing is gated on WalletAccount.hasLocalKeys via _canSignTrades. Ledger and watch-only wallets get a review-only dashboard with explicit copy ("This is a Ledger wallet … on-device signing for trades is not available yet" / "Attach local keys to create or cancel offers"); the per-offer Cancel and Cancel all controls are hidden for them, and the review path ends with a clear message instead of a failed signature.
XRW-28
Raw exception text persisted to the DB		 trade_executions.last_error is now written only as fixed slugs from tradeErrorCategory(Object) (validation, no-signing-key, network-timeout, stage:<const>, submit-rejected, build-failed, unknown) or engine:<code> for a rejected submit. Test asserts a slug never contains the source exception's message.
XRW-29
Fee and reserve missing from the review		 New XrplRpcClient.fetchOwnerReserveIncrementDrops() (from server_info validated ledger). _createLimitOrder preflights the minimum fee and the owner-reserve increment before the review dialog; _OfferReviewDialog now shows "Estimated network fee", "Reserve while the offer rests", and a funds-locked note, with a safe explanatory fallback if the preflight call fails. The AppConfig.maxFeeDrops (0.1 XRP) sign-time cap is unchanged.
XRW-31
Execution row written before PIN verification		 upsertTradeExecution now runs only after promptAndVerifyWalletPin returns true, with initial status signing. A cancelled or failed PIN prompt no longer leaves an orphan awaiting_approval row in getActiveTradeExecutions().

Also fixed (non-security observations)

  • Stale in-app version. Added AppConfig.appVersionName = '2.0.0'; the Settings → About tile interpolates it instead of the hard-coded "1.0.1".
  • Trade test coverage. Added test/data/payments/offer_construction_test.dart (golden OfferCreate / OfferCancel field construction, XRP↔drops on both sides) and test/ui/trade/trade_dashboard_helpers_test.dart (error mappers, offerAmount including sub-drop rejection). The private _toAmount was promoted to the top-level offerAmount() so the money-critical conversion is unit-tested.
  • Widget-test database warning. test/widget_test.dart now overrides databaseProvider with a shared in-memory AppDatabase; the Drift "created the database class AppDatabase multiple times" warning is gone.

Residual notes

  • Ledger on-device signing for OfferCreate / OfferCancel is still not implemented — Trade is deliberately review-only for Ledger wallets until it is.
  • A successfully submitted trade row is still non-terminal; startup reconciliation of in-flight offers against the ledger remains future work (design doc Phase 3).
  • WalletListController.reload() per-network wallet filtering (no cross-network address dedupe) is unchanged and appears intentional.
  • Build note. This rebuild emitted "generated ELF library contains unobfuscated DWARF debugging information — use --strip". This concerns the intermediate AOT library under build/; the shipped libapp.so is section-clean (verified above), so obfuscation posture is unchanged. Adding --strip to tool/build_release.sh would silence it and drop DWARF from the intermediate too.
  • Gradle/AGP/Kotlin future-deprecation warnings persist; compilation succeeded.
