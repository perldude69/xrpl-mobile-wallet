Secrets & cryptography (MASVS-CRYPTO / MASVS-STORAGE)

AreaFinding
Wallet secrets Mnemonics / family seeds stored only in flutter_secure_storage (Android Keystore) via KeyVault; resetOnError: false documented so a Keystore glitch cannot silently wipe seeds. Secrets are method arguments to PaymentService, never stored on the service or logged.
PIN verifier XRW-03 resolved (re-confirmed) — PBKDF2-SHA256, 120k iterations, 16-byte Random.secure salt, constant-time hashEquals, transparent legacy SHA-256 → PBKDF2 upgrade on next successful unlock.
Auto-lock Pass (device-verified) — LockController.lock() after 90 s in background (LockLifecycle, AppConfig.autoLockSeconds). See § Screen capture & device checks.
Failed attempts XRW-02 — in-memory counter only (accepted). Game-PIN decoy after 3 fails is also in-memory.
PIN vs KEK XRW-19 — the PIN is an application lock, not a key-encryption key; Keystore guards the seeds (accepted by design).
Export WalletExport: AES-256-GCM + PBKDF2-SHA256; envelope contains names + addresses only (no secrets); iteration count clamped 120k–600k against weak-KDF / DoS; bounded field lengths.

Background watcher (MASVS-NETWORK / STORAGE)

  • The watcher isolate (watcherOnStart) imports only the public-address book, status store, and rate store — no KeyVault / PinService imports. The shared file is watcher_address_book.json (public addresses + network only).
  • WSS failover is ordered (user prefs → catalog → legacy book value); reconnect uses exponential backoff 2→60 s with a 12 s connect timeout.
  • Seen-hash dedupe is bounded (200 persisted / 500 in-memory) in SharedPreferences — non-sensitive tx hashes only.
  • Notifications contain label, tx type, amount, direction — no secrets. Amounts + labels can be visible on the lock screen (see note N-1).
  • The foreground-service notification shows host only (query string dropped by EndpointUrl.hostOf) — matches the no-URL-leak rule.

Logging & data leakage (MASVS-STORAGE-2)

  • Full-session logcat scan on the installed release while setting a PIN, unlocking, and navigating: no mnemonics, seeds, PIN digits, or private key material from the app. (Test harness artifacts only: adb shell input text commands echo in adbd logs — that is the audit tooling, not the app.)
  • XRW-21 resolved — vendored Ledger plugin: new LedgerLog gates all Log.i / w / e behind BuildConfig.DEBUG; release logcat shows no LedgerUSB lines. Dart-side APDU dumps remain kDebugMode-gated (XRW-10).
  • SQLite (Drift) stores only public metadata: labels, addresses, accent color, useLedger, ledger index. No secrets in the DB.

Auto-lock timing test

Unlock → KEYCODE_HOME → wait 100 s → relaunch → UI hierarchy shows "Enter your PIN to unlock". The first readings in this session appeared to show the app still unlocked after 100 s in background; those were stale uiautomator dump files (the dump step failed silently and an old XML was re-read). Re-tested with a file-freshness guard (rm before, existence check after): auto-lock engages correctly. Control: resume after ~7 s background → stays unlocked (expected, under 90 s).

Other dynamic observations

  • First launch shows the system notification-permission prompt; grant / deny both leave the wallet functional.
  • Discarding an in-progress wallet creation exits the process (SystemNavigator.pop path) rather than returning to an unlocked shell — matches the AGENTS.md exit rule.
  • Test data created during the audit (test PIN, throwaway "AuditWallet" flow state) was wiped with adb shell pm clear afterwards.

New notes from this round (no XRW ID; not actionable as vulnerabilities)

  • N-1 (privacy note): watcher notifications include wallet label, amount, and direction; on the lock screen Android may show these by default. Consider a future "hide amounts" toggle; users can also disable lock-screen notification content in system settings.
  • N-2 (residual risk): debug-keystore fail-open in build.gradle.kts remains as a foot-gun for CI. Suggested hardening: fail the build when key.properties is missing for release builds, or keep the fallback but add a runtime "debug-signed build" banner.
